# Relay 0.3.4: complete interaction-window teardown

## Failure and correction

The 0.3.3 game screenshot shows a Relay panel still rendered after Escape released its input capture, with a second interaction opened over it. Relay called `UFGGameUI::RemoveInteractWidget`, the stack-management API, rather than the Blueprint window teardown entry point `PopWidget`. The pinned SDK's retained `AFGBuildable::CloseAllInteractUIsWithBuildable` implementation calls `PopWidget` to close building panels. `FGGameUI.h` exposes these as separate APIs.

All Relay close entry points now call `PopWidget(this)`. The operation is idempotent: duplicate Escape/click events cannot close another panel. Polling timers and snapshot subscriptions stop immediately, the UMG/Slate panel collapses and discards its content, and parent detachment also handles a missing owning HUD. Cleanup does not depend on destruction happening immediately. Delayed initialization and replies cannot revive a closed widget. A fresh interaction creates a new instance; caching and stacking remain disabled.

`NativeOnPreviewKeyDown` handles Escape before editable fields can consume it. The native `OnEscapePressed` event and Close button use the same close method. This follows the input/close-event conventions described in the [SML interaction guide](https://docs.ficsit.app/satisfactory-modding/latest/Development/BeginnersGuide/SimpleMod/machines/SimpleInteraction.html).

No model, port, save format, transport, or item/fluid logic changes are included.

## Validation

The Linux editor, Steam/Epic Win64 Shipping clients and Win64 dedicated-server module compiled. Both Windows targets cooked and staged successfully, with AutomationTool exit code 0. Import and content inspection completed with zero errors.

All three native automation tests passed with zero test warnings/errors and editor process exit code 0: `Relay.Interaction.CloseLifecycle`, `Relay.Interaction.NativeWidgetLifecycle`, and `Relay.PowerVisual.RejectFactoryWorkerUpdates`. See [automation results](0.3.4-automation.json). Source and asset validation also passed; see [validation output](0.3.4-validation.txt). The corrected controller-owned test fixture is editor-only and does not change the compiled Shipping implementation.

The new `Relay.Interaction.CloseLifecycle` test creates real UMG and Slate parents and retains the Slate wrapper after close, reproducing delayed destruction. It checks all three close entry points, immediate invisibility/detachment, snapshot unsubscription, repeated close, delayed Init, preservation of a neighbouring panel, and reopening with a fresh widget. Source validation requires the native `PopWidget` call and rejects the old direct stack-removal call or a global `PopAllWidgets` workaround.

The editor's FactoryGame UI implementation is partly stubbed, so this test does not execute the shipping `BP_GameUI` presentation graph. Live game acceptance is still required for native focus restoration and interaction with other mods.

## Install test

Restart the game when installing 0.3.4; that also clears already orphaned panels from 0.3.3. Open an endpoint, click into Search, Label and Route fields, and press Escape from each. Repeat with the Close button and the hub panel. After every close, confirm the panel disappears and normal game controls return. Reopen several times, then open another machine/mod interface and confirm only that new window remains. Repeat on a joining client when available.

The log line `Relay: closed interaction ... native pop=true` confirms the native presentation call accepted the close. A false result indicates the native host was absent or rejected the pop; local visual cleanup still runs.
