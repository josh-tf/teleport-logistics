# Relay 0.3.3: interaction, connector housings and hub power alignment

## Changes

The 0.3.2 screenshot showed the use prompt but pressing E did not open a panel. Relay had no native `mInteractWidgetSoftClass` assigned and instead tried to create/push the panel itself, with silent early returns when its remote-call object or widget request was unavailable. All five buildings now register `URelayWidget` and call the inherited buildable use handler. In the checked SDK, that handler invokes `AFGHUD::OpenInteractUI`, the normal game UI opening path. This follows the [SML machine interaction guide](https://docs.ficsit.app/satisfactory-modding/latest/Development/BeginnersGuide/SimpleMod/machines/SimpleInteraction.html).

The widget initializes from native `mInteractObject` in its Init/Construct lifecycle, including when Slate was created before the building context arrived. It disables pooling, clears polling/delegate state on destruction and retries player-owned RCO lookup while displaying a waiting message. The panel no longer needs an RCO merely to open. Log messages identify use dispatch, widget construction and connection readiness for the next in-game test.

The pipe reference is a mounting collar with an open rear. Its approximately 100 cm radius did not meet Relay's 43 cm process neck. Both fluid meshes now have a closed, ribbed pressure reducer and rear flange between these surfaces. Both item meshes have rear shoulder panels and a top cover around the conveyor collar; their conveyor throats remain open. Native belt and pipe origins, rotation, and source connector geometry are retained.

The custom hub mast is retained. The power component moves from the rear insulator at `(-155, 88, 285)` to `(-102, -28, 415)`, within 0.5 cm of the custom mast cap at z=414.5 cm. The connection component has no authored wire-location overrides, so its position controls the cable endpoint. The former position sat below the roof. BeginPlay reapplies the class-default socket transform so a saved component transform cannot restore that old position. The native wire class saves its mesh endpoint positions, so an existing cable may need to be dismantled and reconnected once after updating.

The model nameplates, build menu descriptors and native interaction display names use the requested names: ITEM RELAY (IN), ITEM RELAY (OUT), FLUID RELAY (IN), FLUID RELAY (OUT), and RELAY HUB. Existing user-assigned labels and class/save identifiers are unchanged. Floating extruded lettering is replaced by flat, non-emissive stencil mesh decals seated on small service plates. These use the existing factory atlas and do not add a new material slot. Plate bounds and glyph planarity are checked during generation. The native connector caution and flow decals remain the main directional graphics.

The 0.3.2 game-thread hub power fix is retained. No save fields or cargo formats change.

- Existing `Relay.PowerVisual.RejectFactoryWorkerUpdates` regression remains in the engine test suite.

The editor compiled successfully, and both native automation tests passed with zero test warnings/errors and process exit code 0. See [0.3.3-automation.json](0.3.3-automation.json). The Unreal importer and content inspector also passed with zero errors, including the native widget reference on all five building class defaults. Steam/Epic Win64 Shipping client modules and the Win64 dedicated-server module compiled successfully. The final corrected assets were reimported and inspected with zero errors, then both platforms cooked and staged successfully. The final recook completed with AutomationTool exit code 0. The hub screen housings now follow the actual console top plane; the final 256/512 hub and milestone captures include this geometry.

## In-game checks

With the game closed, replace the existing Relay plugin with 0.3.3. Load the same save and press E on an existing item endpoint, fluid endpoint and hub. Each should open the matching panel, receive data and close with Escape. Test reopening and a joining client. Inspect connector backs and connected belts/pipes from both sides. Connect a power line to the hub and check that it meets the custom mast cap; reconnect an existing line if its saved mesh still uses the old position. These native game interactions still require hands-on acceptance; editor tests do not execute the shipping game's Blueprint UI stack.

If opening still fails, the new log entries starting `Relay: use`, `Relay: interaction widget constructed` and `Relay: interaction connection ready` narrow the failure to dispatch, UI creation or networking respectively.
