# Relay 0.4.1 model refinement

A dedicated hard-surface design agent rebuilt the five source meshes against the
user-supplied concept. These are actual generated OBJ meshes and imported Unreal
assets, not images substituted for models. The design keeps existing route and
channel semantics: IN receives from belts/pipes into the network; OUT supplies
belts/pipes from the network. The concept image's reversed explanatory captions
were not adopted.

## Visual changes

- Layered silver perimeter rails and roof frames, fasteners, dark insets and
  orange armor unify the family. Detail remains in the native factory atlas so
  primary/secondary paint and finishes remain supported.
- Item relays retain the circular field, with a deliberate lateral machinery bay
  that reveals it. A solid rear bulkhead closes the original unwanted opening.
- Fluid nodes have stacked pressure caps and flange detail with compact lamps.
- The hub is rebuilt as a left/back tower, low operator console and separate
  power cabinet with connecting hoses. It has no nonuniform stretch transform.
  Its footprint remains approximately 6 m wide by 3 m deep and 3 m tall.
- Displays are flush planar faces with explicit UVs into a 2048x1024 atlas: cargo
  and direction, droplet and direction, network, and power glyphs. The atlas
  replaces the old graph-paper texture and raised readout bars at the same asset
  path. Screen reflections are reduced; the existing power parameter gates both
  visible screen color and emission.
- The redundant decorative stock power connector is removed. The custom mast is
  the hub's single visible wire connection; runtime socket position is unchanged.

## Render review

First-pass renders exposed excessive item shoulder coverage, a support crossing
one hub display, unsupported fluid braces and an overly silver roof. A second
geometry pass opened the item side bay, shortened the support behind the screen,
removed the loose braces and added a dark roof inset with a thin direction mark.
The second-pass renders are retained beside the first for comparison.

The studio preview uses neutral lighting and graphite secondary paint instead of
the vendor UV sheet's violet paint key. It approximates material appearance;
actual Satisfactory lighting, factory shader parameters and custom finishes need
an in-game check. CPU rendering was limited to one thread, without GPU rendering.

## Integration and validation

Belt and pipe hardware keeps its native geometry, scale and connector transforms.
The power socket remains (-83.64,+52.5,298.8) cm in Unreal local space. Source geometry
checks and an editor test compare the mast cap to this socket. All new lamps use
the signal section and displays use the screen section, preserving off-state
control. Models retain a single source LOD to avoid the previous material changes
at short viewing distances. Hub material sections reduce to factory/signal/screen.

See 0.4.1-validation.txt and 0.4.1-automation.json for final results. No shipping-game
visual or multiplayer acceptance is claimed from editor tests.

The design agent audited the final exported meshes: finite positions/UVs/normals,
unit normals, nondegenerate triangles, and 462 rear-closure rays per item model.
The five meshes total 138,402 triangles (25,582 item input; 25,583 item output;
27,916 fluid input; 28,015 fluid output; 31,306 hub). Every display face selects
its intended atlas tile with an inset margin. Existing native belt/pipe geometry
and source mast alignment checks pass.

Final Windows client and dedicated-server builds/cooks succeeded with 34 packages
each. Four native tests and all source/transport/asset checks passed. Versioned
archives and checksums are available in dist/. No public upload was performed.
