# Relay 0.5.4 startup correction candidate

## Evidence and limits

The user's fresh-map test loads when Relay is disabled with the other mods unchanged. Relay 0.5.1 and 0.5.2 both fail with the same invalid construction-script reference. Version 0.5.3 instrumentation identifies the native `/Game/FactoryGame/Equipment/BuildGun/BP_BuildGun.BP_BuildGun_C` immediately before the assertion, confirmed by both log and crash context.

This establishes Relay as a required trigger in this configuration, not the exact corruption mechanism. No runtime evidence yet proves the reward-loading change is the sole cause. This build is a targeted correction candidate requiring retail-game testing.

## Change

The 0.5.1 reward-display change synchronously loaded and instantiated stock `BP_UnlockRecipe` objects within native milestone constructors. That introduces Blueprint UI dependency loading during native class construction. Restore native default recipe-unlock subobjects in the constructors, and load/create the stock reward presentation during game-instance initialization after native CDO construction has completed.

The presentation replacement preserves all five logistics recipes and the Personnel recipe, remains referenced by the schematic's reflected unlock array, and is idempotent across repeated initialization. If the Blueprint or required fields cannot be resolved, native recipe unlocks remain available and an error is logged. Milestone tiers, costs, class identifiers and models are unchanged.

Construction tracing is retained only for the Build Gun to avoid the all-actor logging/flush overhead of 0.5.3.

## Validation

The content inspection now explicitly checks native constructor reward types, the deferred stock Blueprint interface, preserved reward counts and idempotency. Editor/build/package outcomes are recorded below.

If construction still crashes, provide the new log and crash context, which retain Build Gun tracing. Do not treat successful compilation as proof that the retail crash is fixed.
