# Relay 0.4.0 — native UI, SFUIKIT and connector corrections

The endpoint layout follows the supplied design: identity strip, routing column,
assignment preview, throughput/state, local buffer, standby and isolated flush
controls. The hub uses a route browser, route management column and paginated
endpoint directory. A channel dropdown accommodates many hubs. The directory
filter explicitly applies to the current page.

Runtime framing uses Widget_Window_DarkMode, its WindowBody named slot and
OnClose delegate. Routine actions use Widget_StandardButton; route rows and
custom controls are Slate. SFUIKIT supplies resizable panel, recessed well and
white display artwork. Native Heebo fonts and Relay's model captures provide
typography and identity. Native Blueprint widget contracts are verified against
the installed SDK. The reconstructed SDK has stubbed visual graphs; worldless
editor tests use the equivalent Slate frame/buttons. Live game visual acceptance
is still necessary.

Panel assets are from Deantendo/Treelo's SFUIKIT at revision
 e374ed1ee05ecda5834bb9fa38adb928ebe56b4f, CC BY-SA 4.0. Sources, derived artwork,
export script and attribution are included. Resources/SFUIKIT-NOTICE.md is staged
with the installable plugin.

- Applying names/routes waits for a server mutation revision and result. Rejected
  changes retain the draft, display the server reason and allow correction.
- Polling retains typed text and existing route widgets when only metrics change.
- Buffered quantity, enabled state, route counts and reset eligibility come from
  the server. Clients do not read the server-only cargo array.
- The unpowered hub disables management and explains that transport continues.
- Delete/reset/flush have in-window confirmations. Background controls are
  disabled while confirming. Escape still closes the entire Relay interaction.
- Window dimensions are bounded by available logical space. Body content scrolls
  in constrained viewports instead of shrinking all text. Standard controls remain
  keyboard focusable, with native Escape/PopWidget teardown retained from 0.3.4.

## Reported connector issues

Unreal's OBJ conversion mirrors Blender's Y axis. The final hub is proportioned
into an approximately 6 m wide, 3 m deep, 3 m high console envelope. Round mast
hardware is preserved, and the socket moves with the geometry to
(-83.64,+52.5,298.8) cm. An automation assertion measures the imported mast
vertex buffer against the actual socket, instead of trusting source coordinates.
The size target follows the [published crafting-bench dimensions](https://satisfactory.wiki.gg/wiki/Crafting_Bench).
The installed SDK's stock mesh is a placeholder cube, so its mesh bounds were
not used as the scale reference. Live side-by-side visual acceptance remains necessary.

Existing wire instances retain independently saved endpoints. A game-thread
refresh repairs only wires attached to this hub, their relative mesh anchors and
replicated endpoint positions. It retains the far endpoint and circuit links.

Item relays now have a solid rear bulkhead and mounted service panel behind the
field assembly. The front connector throat and original port origin are retained.
Both item descriptor capture pairs were regenerated. The inspected Blender rear
render shows the formerly open housing closed; studio materials are proxies for
native game materials.

Transport endpoints opt out of the factory's managed idle tick rate and request
zero factory tick interval. This addresses an inherited throttling path that can
cause intake pauses. The reported perceptual delay still needs an in-game test
with a supplying belt and available route/output capacity; intentional downstream
backpressure must continue to stop intake when buffers fill.

## Map markers and hub lighting

The native Widget_MapObject uses Widget_MapCompass_Icon and its material brush.
Relay previously returned a sidebar texture but a null compass material. Five
persistent material instances now follow the native MI_CompassIcon_Static /
MI_CompassIcon_Portal convention, binding each Relay texture to the native Icon
parameter. Both texture and material references are retained on the building and
passed to the native replicated representation. No transient MID is replicated.
Inspection checks all five CDO bindings, parent materials and texture overrides.

The SDK strips the master material graph, so its editor parameter-name lookup is
empty. The asset generator copies the verified native portal's serialized Icon
parameter record and replaces its texture. Runtime uses the game's master shader.

Hub control requires a connected, powered, non-tripped power-info circuit. The off
state uses an authored zero-emission lamp material instead of relying on the
native factory LOD material's primitive data. The screen multiplier becomes zero for both its visible grid colour and emission, leaving dark glass.
The game-thread refresh also repairs material overrides changed by customization
even if the power state itself has not changed. Factory workers still never touch
materials or renderer state. Automation covers off/on/off transitions and restoring
overrides after simulated customization, in addition to the worker-thread guard.

## Validation and limits

See the adjacent source/native test reports and release checks. Native lifecycle,
server snapshot handling, draft retention, stale reply rejection, close teardown,
worker-thread rendering guard and imported mast position are tested. The native
window contract test can emit warnings from reconstructed base-game Blueprint
event stubs; these are not shipping Relay graph errors.

An attempted offscreen Unreal UI capture required software Vulkan and shader
compilation. The capture process was killed during VM resource trouble before
screenshots completed; orphaned workers were cleaned up and the remaining build
was restricted to one job. No claim of successful rendered native UI screenshots
or multiplayer gameplay acceptance is made.

Final source checks passed seven transport scenarios with 60,000 randomized
conservation steps under address/undefined-behaviour sanitizers. All 34 retained
packages and native map bindings passed content inspection. All four native tests
passed (one test has 25 reconstructed base-game Blueprint warnings). The final
imported mast cap measures (-83.640,+52.500,298.781) cm, within 0.02 cm of the
socket. These are editor/data checks; live Windows visual and multiplayer checks
in docs/validation.md remain pending.

The final Steam/Epic and Windows dedicated-server Shipping builds and both cooks
succeeded. Each IoStore container contains all 34 packages. The checked release
archives are in dist/; their hashes are in dist/SHA256SUMS. No public upload was
performed.
