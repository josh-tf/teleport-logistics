# TeleportLogistics 0.5.10: internal rename

Branch: `refactor/teleporter-internal-rename`. Baseline: `20e9fa8` (0.5.9). No publication or game installation performed.

This release migrates the plugin directory/manifest, C++ module and export macro, all 40 reflected classes, six structs, one enum, saved endpoint identity property, material power parameter, all 41 cooked-content source packages, model/texture source filenames, automation namespaces, build/packaging scripts and offline viewer keys/filename to **Teleporter**.

Unreal AssetTools performed the binary package rename. The first attempt correctly refused while old native class defaults held references; migration was rerun with the old module unloaded. The migrated graph uses `/Teleporter`, with renamed objects, and the screen material retains its prior graph with `TeleporterPower`. No binary search-and-replace was used. A subsequent clean import from the renamed sources removes stale Interchange destination metadata and LOD reimport paths that AssetTools does not rewrite.

Legacy references remain deliberately in `Config/DefaultTeleporter.ini`, the migration inventory/verifier, compatibility tests and historical reports. Current code does not depend on the old Relay module. Third-party dependencies were preserved without renaming their unrelated relay terminology.

## Second rename to TeleportLogistics

The SMR reference `Teleporter` belongs to an existing player-teleport mod (`Bk37KmQuPNpDvK`, 333k downloads,
last released 2024-06-30), and SMR requires the reference to match the plugin and native module. The identity
therefore moved again, to `TeleportLogistics`, before any publication. `Relay` and `TeleportLogistics` were
both verified free against the SMR API, which also confirms nothing from this project has ever been published.

Scope of the second pass: plugin directory and descriptor, C++ module and export macro, all 40 reflected
classes, six structs, one enum, the log category, the internal scheduler namespace, source filenames,
automation test paths, access transformer friend classes, asset mount, build/packaging scripts and viewer
keys. Serialized names were deliberately left alone: asset object names, the saved endpoint identity field,
the screen material scalar and subobject names keep their `Teleporter` spelling because they match the
building names, which do not change, and re-renaming serialized data would add migration risk for no player
benefit. Player-visible building names are unchanged; the two milestones and two map categories now read
Teleport Logistics and Teleport Personnel.

Redirects cover both old identities in one table: 134 entries from Relay and 131 from Teleporter, plus a
property redirect keyed on the current class for saves that still store `RelayId`. That last entry was
missing at first and the native suite caught it: property redirects resolve after the class redirect, so the
lookup happens against the new class and an entry keyed on the old one never matches.

## Validation

- Standalone scheduler/model/source/archive checks passed after source rename.
- Offline viewer passed using Teleporter-only source paths and data keys, all six models, camera modes and mobile layout.
- Linux native editor/SDK rebuild passed (108 actions). Follow-up test build passed.
- All nine `TeleportLogistics.*` native automation tests passed, including legacy soft-path redirects for 41 assets, 39 classes, six structs and one enum, plus the saved GUID property redirect/flags.
- The migration verifier loaded all new assets/types, checked hard/soft package dependencies for old mounts, updated import provenance, and verified `TeleporterPower`.
- Content inspection passed: retained meshes/LODs, materials, research costs/rewards and distinct milestone icons.
- Windows Shipping client/server packaging passed after the rename (Alpakit `PackagePlugin`, Win64 client and
  server built separately, exit 0 each). The first combined attempt was killed by this host's memory guardrail
  at 143 of 272 actions, not by a build error: MSVC under Wine holds about 1.9 GB per compile action, so the
  rebuild used one action at a time and split the targets. Renaming the access transformer friend classes
  forces a full FactoryGame recompile per target, which is what makes this rename expensive to build.
- Release archives assembled and verified from those staged plugins: `dist/Teleporter-0.5.10{-Windows,-WindowsServer,}.zip`,
  plus the source handoff archive and `dist/SHA256SUMS`. Staging strips config comments and adds a BOM, so the packaging
  check compares redirect directives rather than raw bytes.
- The legacy saved-field check in `Teleporter.Persistence.LegacyRedirects` writes an endpoint with the old `RelayId`
  property name and reads it back into `TeleporterId`; all nine native tests pass with it enabled.

Direct `unreal.load_asset` applies package-only resolution and is not a valid assertion for renamed object soft paths. The native test explicitly exercises `FSoftObjectPath::FixupCoreRedirects` and loading against the expected new objects. These checks do not claim a full retail save migration has been tested.

Viewer screenshots are in [model-renders/0.5.10](model-renders/0.5.10).

## Upgrade

Disable the old Relay installation before installing Teleporter. Server and clients must use the same new version. Keep a backup save and the old 0.5.9 package. Explicit redirects support legacy name resolution, but only loading, checking and resaving an actual game world can establish complete save migration. Old mod metadata may still trigger a missing-mod warning. No backwards compatibility is promised for a save resaved under Teleporter.

See [migration instructions](../docs/migration/README.md), [retail acceptance](../docs/validation.md), and [publication kit](../docs/publishing/README.md). The physical nameplates and existing custom names are unchanged by this internal-reference migration.

## Redirect removal before release

The compatibility redirects were removed after the checks above were recorded. The earlier Relay and Teleporter
identities were never published and only the author's own test saves used them, so the shipped package carries no
`[CoreRedirects]` config, and `docs/migration/`, `scripts/verify-migration.py` and the
`TeleportLogistics.Persistence.LegacyRedirects` automation test were deleted with it. The redirect results above
stand as a record of what was verified while the redirects existed; they no longer describe the shipped archive.
The automation suite is eight tests from this point.

The identification-plate atlas was relettered in the same pass. It had kept its original lettering for save-visual
continuity, which no longer applies. `scripts/generate-detail-atlas.py` now also fits the type to its tile: the
longest label had grown to 528 px inside a 512 px tile, which would have bled into the neighbouring plate's UV
rectangle.
